## ⭐ LONG侧改造第一推进方案：横截面排名特征 + 大盘 regime 特征（2026-08-26 立项）

**证据链（2026-08-26 分析）**：
- 8/8 起 IC_L 持续为负（17天中14天），但 AUC_L 已回基线（8/24 单日 0.690）——**分类能力活着、排序死了**
- 分桶分解：LONG 头部桶（top1-10）14日均 +0.49% vs 宇宙均值 +1.00%，排序 alpha 为负；SHORT 头部桶 -5.59% 教科书级正确
- 8/18-20 暴拉期梯度完全倒挂（8/19 尾部 +11.97% vs 头部 +0.86%）——**轮动补涨行情，模型排序编码动量风格，反向挨打**
- 真实盈亏：8/8 起 17 天 LONG 170笔 +63.4U（0.37U/笔）靠 beta+机制续命，SHORT 170笔 +234.2U 贡献 79% 利润

**病根**：模型只看单币自身时序特征（900+ 全是 RSI/动量/OI 等），**看不见自己在宇宙里的相对位置**。"上月输家补涨"是横截面信息，任何单币时序特征都编码不了。

**改法（特征层，不动标签不动损失函数）**：
1. 横截面排名特征组：每币的 7d/30d 收益宇宙 rank、成交额热度 rank、换手 rank、距 30d 高点回撤 rank（低 rank = 超跌补涨候选）
2. 大盘 regime 特征组：BTC 30d 已实现波动率、BTC 距前高、宇宙动量因子 5 日滚动值（让模型学"暴拉期谁补涨"）

**注意**：现有宏观特征（SP500/DXY）周末缺失是**休市事实，不是数据缺失**——周末填 0 在"市场关闭"语义下可辩护（该不该 ffill 归 P2 独立验证，与本方案无关）。本方案的 regime 特征用 crypto 原生数据（BTC/宇宙），7×24 无休市问题。

**验证**：GPU 180d A/B（XS_RANK 臂），对比实验前清缓存 `rm -rf by_day_cache/*`，TOP1 参数不动。
**后续队列**（本方案出结果后依次推进）：A 残差化标签（超额收益标签，掐 beta 病根，全链路改动最大）→ C LambdaRank 排序损失（直修 IC，下游语义需重校准）→ D 新数据源（taker ratio/大户持仓/orderbook 失衡，先探 Binance 历史深度）。

## ⭐⭐ 系统利润周期与 BTC 波动 regime 绑定（2026-08-28 确立，核心认知）

**证据链（2026-08-28 分析，30 天样本）**：
- BTC 5日已实现波动 vs AUC_L：**r=-0.52, t=-3.79**（显著负相关）；vs AUC_S：r=-0.36（不显著）
- 高波动天（>2%，n=7）AUC_L 均值 0.491 vs 低波动天（≤2%，n=23）0.660——**LONG 侧对波动敏感，SHORT 侧基本免疫**
- 8月完整样本：18 天平静期（vol 0.3-1.5%）双侧吃 alpha → 4 天冲击期（vol 2.7-3.6%）LONG AUC 崩至 0.24、SHORT 侧暴拉普跌中 AUC_S 反冲 0.92 → 回平静期（vol 1.1%）双侧恢复
- 两侧利润**都产自平静市**：LONG 吃横盘温和 beta+机制钱（0.37U/笔），SHORT 吃横盘里独立选币的暴跌捕获（8/3-8/18 贡献几乎全部利润 +996% 端点基数）；波动大市两侧都挨打（LONG 挨轮动反转、SHORT 挨逼空）

**本质**：这个系统吃的就是横盘期 alpha。BTC 波动率是利润周期的主时钟：

| regime | BTC 5日vol | 系统状态 | 动作 |
|---|---|---|---|
| 平静期（吃 alpha 窗口） | ≤1.5% | 双侧正常 | 全档运行 |
| 波动期（挨打/等待） | >2% | LONG 分类力崩、SHORT 独立alpha仍可 | 降 LONG 档、SHORT 保持、SL 兜底 |
| 恢复期 | 回落中 | AUC_L 谷底后连续回升 2-3 天 | 观察恢复 |

**D+2 AUC 确认信号的正确预期**（时序物理）：48h 标签 → 质量确认最早 D+2 早报。对隔日快冲击是追认（8/18 的 AUC 崩实际是被窗口内的 8/19 暴拉打崩，非领先信号）；**对持续 5 天+ 冲击有真实价值**——第 2 天确认后剩余天数全程降档（8月案例：若 8/20 早报降 LONG，8/19-8/21 三天半仓）。crypto 冲击多为持续数日，急跌一天结束的是少数。

**已上线（晨报 4a4，commit 392aad2）**：7日批作业表加 BTCvol 列；AUC_L<0.55 且当日 vol≤2% → 🚨"8/18形态"提示（失效始于平静市）；当日 vol>2% → ℹ️冲击兑现期提示。

**待办（本条目下的后续动作）**：
- [ ] 仓位节律规则化（需更多样本校准阈值）：AUC_L≥0.60 全档 → D+2 确认跌破 0.55 降 LONG 档 → 谷底后回升 2 天恢复观察 → 回稳 0.60 恢复全档
- [ ] 与 ⭐ LONG侧方案 regime 特征组（BTC 30d 已实现波动率）同源——让模型自己看见环境，比人看 D+2 报警更治本

## P0：训练/推理不对称（唯一"预期必然为正"项）

**问题**：预测端剔除 5 日均成交额 <500,000U 的币（`auto_dual_trade.py:2020` MIN_VOLUME_24H），但**训练集零过滤**——日均 1 万 U 的死币照样参与训练。模型在低流动性分布上学到的模式，实盘永远用不到；高流动性币的样本被噪声稀释。回测无法暴露（回测执行过滤与生产一致，训练侧同样不过滤）。

**改法**：训练样本构建时加同款过滤（样本日的前 5 日均成交额 ≥500,000U 才入训练集）。
**验证**：GPU 180d A/B（gpu_backtest_exp.py 加 VOLUME_FILTER 臂，照 MIN_KLINES 模式）。预期样本量 -30% 左右，Sharpe 持平或升。
**位置**：`auto_dual_trade.py` 阶段2样本构建循环（L851 起）+ `gpu_backtest_exp.py` 同源段。
**注意**：MIN_VOLUME_24H=500000 本身无实验背书（拍脑袋值），A/B 时顺带做 30 万/50 万/100 万三档敏感性。

## P1：OI 特征半程失明

**问题**：`fetch_oi_for_symbols` 只取最近 90 个 OI 快照（`auto_dual_trade.py:783` 的 `[:90]`），但训练窗 180 天 → 前半程样本 oi_chg 恒为 0，且"缺数据"与"OI 真没变"不可区分。oi_daily.json 本身是累积合并的（历史更长），截断疑似 Binance API limit=90 的被动继承，无注释无实验。

**改法**：放开 `[:90]` 截断，取全量历史。
**验证**：GPU 180d A/B（注意 oi_chg 特征分布前后对比，确认前半程不再恒零）。
**风险**：低——纯数据覆盖扩展，不动任何逻辑。

## P2：缺失值语义混淆（宏观特征周末归零）

**问题**：宏观/板块/ETF/费率缺失一律填 0（`daily_predictor.py:527-552`，无 ffill），NaN 也填 0。SP500/DXY 每个周末整列变 0 → "无数据/中性/零收益"三态不可分。
**用户澄清（2026-08-26）**：SP500/DXY 周末缺失是**休市事实**，不是数据缺失——周末本就没有交易。填 0 的问题不是"数据丢了"，而是"休市（应延续周五收盘状态）"和"宏观真崩了（0）"两个语义被压成同一个值，模型无法区分。

**改法**（二选一，A 成本低）：
- A：缺失时 ffill 前值（周末宏观=周五收盘值）
- B：加缺失指示位特征（维度 946→+宏观组数量，涉及 EXPECTED_N 断言，改动大）

**验证**：GPU 180d A/B（MACRO_FFILL 臂）。
