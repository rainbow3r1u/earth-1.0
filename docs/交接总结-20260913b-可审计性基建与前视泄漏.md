## 1. 最重要的事：GPU 缓存的一日前视泄漏（dim13-16）

### 1.1 怎么被发现的
用户质询"**8/3 的模型是不是现在的模型？每天都在服务器上动来动去**" → 做谱系验证时发现：用"当前代码 + 当前数据"重建 8/20 的预测，与生产公证存档的 Spearman **只有 0.20**（top10 重合 0/10），
而**概率饱和到 96%**（生产 87.9%）。**用户当场指出："上次抓到幽灵问题，就是因为这个概率"** → 顺着这个签名查下去。

### 1.2 定位链（每一步都有检验）
1. **排除标签损坏**：缓存 `ret` 列 = open→close 两日收益，命中 400/400；`ll≡(ret>5%)` 一致率 1.000 ✅
2. **排除特征整体错位**：逐币 946 维相关 = 1.000 ✅
3. **篡改检验（决定性）**：把样本日 D 的 K 线人为改掉（收盘×3）→ 该日特征**固定 4 维变化**：**dim13/14/15/16**
   （全宇宙篡改后仍只这 4 维 → 板块热度不泄漏）
4. **反推维名**：按 `assemble_feature_vec` 参数顺序 → **dim13-16 = r2 / residual / rsi7 / rsi14**
   👉 **泄漏的正是"对BTC残差传感器"的核心几维**
5. **机制**：生产 **08:05** 构建时当天 bar 尚不存在（07:30 采集只到前一日）→ 那 4 维用**前一日**数据（**无前视**）；
   而 GPU 从**全量历史K线**构建 → 当天 bar 在 → 这 4 维吃到**当天收盘价** → **一日前视**

### 1.3 修复与量化
- 修复产物：GPU 端 `by_day_cache_v5_aligned_volraw_fund_noleak`（每个(币,日)样本 dims13-16 替换为前一日样本值；**2113 天 / 修正 326,282 样本 / 18 秒**）

|---|---|

### 1.6 不可复原的边界（诚实记录）

导致生产侧那 3 维长期为 0，而用今天的文件重建就有值。

## 3. 可审计性三件套（新基建，全部已上线）

> 起因：用户问"**以后有没有标尺可以测量模型是否被改过？**"
> 现状：模型 pkl 只留 5 天且从不入 git（三重屏障：仓库外目录 + `.gitignore` + 同步脚本排除扩展名）

### 3.1 模型标尺 `scripts/model_probe.py`（cron **08:36**，账本 `data/model_probe.jsonl`）
- **原理**：冻结一份特征输入（`data/pred_feats_2026-09-13.npz`，feats+bounds，MD5 `06a94b3be2db`，**永不改变**），
  每天用当日生产模型（SOUP 3 模型）对它推理 → 概率向量记入账本。**输入固定 → 输出变化只能来自模型本身。**
- **判据**：ρ≥0.85 正常 / 0.5~0.85 需查 / **<0.5 模型已实质改变**（历史案例：前视泄漏期 ρ=0.20）
- **实测基线（9/09~9/13）**：ρ 均值 **0.9939**，最低 0.9921 → 每日全量重训的固有漂移仅 **0.6%**
- **⚠️ 关键设计约束：只认固定输入。** 实测对照：固定输入逐日 ρ=0.994；而**生产预测逐日**（输入每日在变）ρ 仅 **0.65**（0.24~0.88）
  → **用变化输入无法区分"数据变了"与"模型变了"**

### 3.2 生产指纹账本 `scripts/prod_fingerprint.py`（cron **08:35**，账本 `data/prod_fingerprint.jsonl`）
每日一行：git HEAD + **7 个生产核心文件 MD5** + 当日模型 pkl MD5 + train_npz MD5 + pred_feats MD5 +
**特征零值图案**（掩码/数据变动可见）+ **13 个外部数据文件 MD5**（回刷可见）+ 工作区未提交改动。
**存哈希不存文件**（pkl 0.86MB×2×365≈630MB/年 无法入 git；哈希一年仅 ~23KB）。

### 3.3 COS 模型归档 `scripts/cos_model_archive.py`（cron **08:40**）
- **查清的事实**：生产本来每日上传 COS，但用**固定 key**（`klines/cache/xgb_daily_long.pkl`）+ bucket **未开版本控制**
  → **8/03 的模型已被 8/04 覆盖，永久丢失**
- **已建**：日期化 key `klines/cache/models/xgb_daily_{long,short}_YYYYMMDD.pkl`（**不覆盖**），已补齐 **0909~0913 共 10 个**

- 成本：模型 0.86MB×2×365 ≈ **630MB/年 ≈ 1 元/年**
- **附带升级**：有了模型实物，"模型是否被改过"从**哈希比对**升级为**实物比对**（可用历史模型跑固定探针）

| 参数 | 一句话 | 它回答 | 谁能改变它 |

| **② 顶部命中率** | 我们 TOP10 选币中达标的占比 | **实际抓到**——榜单有多少笔真吃到大涨 | 模型 × 行情 |
| **③ lift = ②÷①** | 榜单比"随机抓一个币"强几倍 | **模型相对能力**（与行情无关） | **只有模型** |

**判读线（用该档自身全期 lift 当尺子，两档量级不同不可共用绝对阈值）**：
`≥基线×0.8 → ✅完好` / `×0.65~0.8 → 🟡观察` / `<×0.65 且底率恢复≥全期八成 → 🔴模型退化警报` / `底率不足八成 → 不给结论`

**两处必须记住的展示设计**：
1. **⚠️ 粒度警告**：单日只有 10 个选币 → ②命中率只能取 0%/10%/20%…（**10.00% = 恰好 1 个币**，不是"稳定 10% 概率"）；
   逐日表**只看①底率的供给趋势**，不要用单日②③下结论
2. **⚠️ 结构门槛**：300U 名义下 1 笔 +33% ≈ **+99U**，而当日其余 9 笔若止损（SL-5% 每笔 −15.5U）= **−139.5U**
   → **只抓到 1 个 +33% 仍不足以让当日转正，尾部需 ≥+47%（≈+140U）** → 与 §4 到期单均是同一件事

**首次读数（2026-09-13）**：≥+33%档 底率 1.08% / 命中 5.71% / **lift 5.27x（=基线 143%）**
→ **模型尾部能力未退化，缺的是市场供给**。

## 5. 底率分档标尺（新知识，已写入 SKILL §4.6）

**底率 = 全宇宙约540币中，2日涨幅≥+33% 的占比**

| 同窗口底率 | 天数/笔数 | 批次合计 | 每笔均值 | **每笔中位** | **剔TOP3后** | 到期单均 |
|---|---|---|---|---|---|---|
| **<1.0%（荒）** | 12天/120笔 | **−470U** | −3.92U | **−9.43U** | −10.24U | +30.06U |
| **1.0~1.5%（偏紧）** | 10天/100笔 | −148U | −1.47U | **−6.65U** | −8.49U | +34.57U |
| **≥1.5%（正常+）** | 17天/170笔 | **+3186U** | +18.74U | **+12.31U** | **+6.05U** | **+106.36U** |

**读法（稳健性检验后确立）**：
- 排序三列一致 → "荒/偏紧亏、正常赚"**稳健**，不是被个别肥尾日撑出来的
- **均值被尾部拉高**：正常档均值 +18.74U 中前 3 天就贡献 +233.8U，剔掉只剩 **+6.05U/笔**
  → 常态收益看**中位/剔尾**；均值是"含尾部"口径，**不可当预期值**
- 判断"当期亏损是否正常"要拿**中位列**比（荒年中位 −9.43U 比均值 −3.92U 更差）
- 分布参考：25分位 0.93% / 中位 1.48% / 75分位 1.85% / 最低 0.37% / 最高 9.26%

**⚠️ 用途边界（防止被误用成信号）**：
- **底率与 IC 同类，都是"同窗口事后量"**——要等 T2 收盘才结算得出，**入场那天不知道今天的底率**
- 实测相关（当日每笔U）：**同窗口底率 r=+0.266**（诊断力强）；**入场前可见底率 r=+0.046**（**日级预测力≈0**）；IC_L 同口径 r=+0.287
- **正确用途 = 诊断 + 状态判定，不是"今天开不开仓"的闸门**

**铁律：右尾能力看这三个数，不看 IC。** 实测 9/06 IC_L=−0.149 而 lift=9.1x、9/07 IC_L=−0.186 而 lift=13.7x
（IC 深负但顶部照样抓到），与已验证的 8/19、8/25、8/28 三条脱锚同型。
