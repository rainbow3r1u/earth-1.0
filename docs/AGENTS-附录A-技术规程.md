## 8.1 TOP10 全开回测模拟器规范(2026-09-07 立项, 对齐果实盘/刘盘结构口径)

> 目的: FEAT4 组内条件特征的**公平审判** — TOP1+TP10 结构对为尾部设计的特征是"砍尾部的裁判"。模拟器对齐实盘执行器(果 audit/residual_live.py / 刘 audit/hybrid_live.py)的**结构与执行**行为, 六条边界:

| # | 实盘行为 | 模拟器还原 |
|---|---|---|
| 1 | 72h滚动: D日开仓→D+3 08:21到期平仓 | 每笔持有3根日K, 第3根收盘平 |
| 2 | SL-8%盘中触发(挂交易所逐仓; **2026-09-07 由 5% 调**) | 逐日扫 low≤entry×(1−`SL_PCT`)(含入场日); ⚠️ 档位由环境变量给, **跑结构级对照必须显式传 SL_PCT=8**, 否则引擎默认 10% ≠ 实盘 |
| 3 | 重复预测跳过**不补位**(用户拍板) | 已在持币再入TOP10→直接跳过, 不递补第11名 |
| 4 | 止损释放槽位, 当天不补开 | SL触发即移出held集合, 次日可重开 |
| 5 | 到期平仓后同日可重开(8:21平→8:24开) | 时序: 先平到期批, 后开新批, 同币可再入 |
| 6 | 每日新开≤10(实际6~10, 受跳过影响) | TOP10减held=实际开仓数 |

**不模拟资金约束的依据**: 并发账本铁律(2026-09-07) — 实盘峰值23笔×8U=184U保证金, 300U权益从未触顶; 回测按名义等权计pnl%。
**已知口径误差(两臂共担, 不污染A/B差值)**: 回测只有日K, 用open[D]入场+日线h/l扫SL; 实盘是08:21日内入场+真实挂单 — 入场日"开盘前扎针"的假止损误差两臂相同。

## 8.2 GPU 大实验操作规程(2026-09-13 立规, 源于"回测不对齐"事故)

> **⚠️⚠️ 头号诊断规则(2026-09-13 二次验证): 概率饱和 = 前视/泄漏签名。**
> **回测自训模型的 prob 明显高于生产(如回测 96% vs 生产 88%~93%), 第一件事就是查"特征是否用到了样本日当天的 bar"。**
> 该签名已两次抓到真 bug: ① 2026-08-01 幽灵问题(回测 90~100% vs 生产 54~71%);
> ② 2026-09-13 本规程事件 — 实测: 篡改样本日 D 的 K 线 → 该日特征**固定 4 维变化**(dim13/14/15/16);
> 用"前一日样本值"覆盖这 4 维后, 谱系对齐 Spearman **0.2276 → 0.7445**、max_prob **96.1 → 80.4**(生产 87.9) → 泄漏确证。
> **机制**: 生产 08:05 构建时"当天 bar 尚未存在"(07:30 采集只到前一日) → 那 4 维用的是前一日数据, **无前视**;
> 而 GPU 从**全量历史K线**构建 → 当天 bar 在 → 这 4 维吃到当天收盘价 → **一日前视**。
> **影响**: 生产实盘安全(从未泄漏); GPU 回测**绝对水位全部偏高**(含历史 Sharpe 16.8~25, 铁律4 由此有了具体机制);
> 相对 A/B 仍可用(两臂同等泄漏); 用"生产存档选币 + K线"做的分析不受影响。

> **事故回顾**: GPU walk-forward(含SOUP)跑出的 TOP10 与生产 pred 存档重合度仅 **8.3%**,
> GPU侧概率 91~96%(微盘币) vs 生产 57~66(主流币)。根因: GPU 缺 `sentiment_data`/`defillama_data`/
> 清算数据 → **40+ 维市场上下文特征全零** → 用缓存训练出"另一套模型"。**SOUP 无辜**(用生产模型存档
> +pred_feats+SOUP语义可逐位复现生产输出 10/10)。教训: 8/1 那次"生产同源"修复只同源了**代码**,
> 没同源**数据**。已修复(2026-09-13): rsync 三类数据 + 重建缓存(223s) + 特征逐位一致验证通过。

**任何 GPU 大实验(walk-forward / 结构对照 / 闸门检验 / 特征A/B)开跑前, 必须按序过这 7 条, 不达标禁止开跑**:

1. **数据同源**: GPU 上 `sent_features / chain_tvl / liq_features / btc_dominance_proxy` 加载天数与本地一致
   (128 / 3272 / 96 / 482)。一行 python 可验, 30 秒。
2. **特征同源**: 取任一共同日, 重建该日特征 vs 生产 `pred_feats_*.npz` 逐币相关 ≈1.0, 且无"整块全零维"。
3. **仪器标定(最关键)**: 先跑 1~3 天 walk-forward, TOP10 候选与生产 `pred_*.json` 存档对比,
   **重合度 >80% 才算仪器合格**。不达标 → 查数据/特征/过滤, 禁止用不合格仪器跑长窗口。
4. **结算标定**: 自建结算 vs 影子档逐笔一致率 ≥90%(正确口径: 入场=T0开盘, 扫T0..T2的low,
   平T2开盘; 错用"T+1开盘"会错位一天, 一致率掉到66.9%)。
5. **显式传参**: `SL_PCT=8`(默认10≠实盘) / `TOP10_LONG=1`(默认0会返回TOP1 dict而非top10 tuple) /
   `SOUP=1`(生产口径) / 引擎winsor默认走 `dp._fast_winsor_bounds` 与生产一致。
6. **SOUP 状态纯内存、不落盘 → walk-forward 不可中断续跑**(中断后前2天集成数不足, 结果不可比)。
   长跑必须增量落盘(每5天写盘), 中断也有已完成部分。
7. **GPU 严格串行**, 不并行抢资源; 跑完先验证再分析, 不看引擎自带的 Sharpe(那是组合口径, 与逐币检验无关)。

**一键裁判(2026-09-13 加)**: SKILL「仪器标定」`.agents/skills/instrument-calibration/SKILL.md` +
`python3 scripts/instrument_calibrate.py --check|--settlement|--full`
→ 连接/串行/传参/数据同源/结算标定自动化; **GPU 连接信息每次都变, 故脚本不硬编码**: 走 env(GPU_HOST/PORT/USER/PASS) 或 `~/.gpu_conn`(chmod 600, 不入 git), 更新用 `--set-conn HOST:PORT`。
**判据修正(同日)**: 第3条**不要再用"选币重合度>80%"** —— top10 是刀刃(生产自身重训也只重合5/10); 正确判据 = **概率向量 Spearman≥0.90 + 概率不饱和**。

**数字速查**: RTX3060 12GB | 缓存重建 223s(2113天) | walk-forward ≈6s/天(350天≈37min) |
逐币结算与影子档一致率 93.4%(`audit/coin_sim.py`) | 大实验分析脚本 `audit/gate_ext_test.py`。


## 8.3 模型标尺 + 生产指纹账本(2026-09-13 立, 用户指示"以后有标尺可以测量是否被改过")

> **问题**: 模型 pkl 只留 5 天且从不入 git(三重屏障: 仓库外目录 + .gitignore + 同步脚本排除扩展名)
> → "8/03 的模型"事后无法比对。任何"模型被改过没有"的追问此前只能靠考古(2026-09-13 用户质询暴露此洞)。

**① 模型标尺**(`scripts/model_probe.py`, cron 08:36, 账本 `data/model_probe.jsonl`):
- **原理**: 取一份**冻结的特征输入**(`data/pred_feats_2026-09-13.npz`: feats+bounds, 永不改变),
  每天用当日生产模型(Soup 3 模型)对它推理 → 得到固定长度的概率向量记入账本。
  **输入固定 → 输出变化只能来自模型本身**。
- **判据**: ρ≥0.85 正常 / 0.5~0.85 需查 / <0.5 模型已实质改变(历史案例: 前视泄漏期 ρ=0.20)。
- **实测基线(9/09~9/13 五个模型)**: ρ 均值 **0.9939**, 最低 0.9921 → 每日全量重训的固有漂移仅 0.6%。
- **⚠️ 关键设计约束: 标尺只认固定输入。** 实测对照: 同一输入下逐日 ρ=0.994; 而**生产预测逐日**(输入每日在变)
  ρ 仅 0.65(0.24~0.88) → 用变化的输入无法区分"数据变了"与"模型变了"。**任何旧标尺/比对必须固定输入。**
- 输入侧防篡改: 账本记 `probe_md5`; 冻结输入一旦被改, 当天即出现 probe_md5 变化。

**② 生产指纹账本**(`scripts/prod_fingerprint.py`, cron 08:35, 账本 `data/prod_fingerprint.jsonl`):
每日一行: git HEAD + 7 个生产核心文件 MD5 + 当日模型 pkl MD5 + train_npz MD5 + pred_feats MD5 +
**特征零值图案**(掩码/数据变动可见) + **13 个外部数据文件 MD5**(回刷可见) + 工作区未提交改动。
**存哈希不存文件**(pkl 0.86MB×2×365≈630MB/年 无法入 git; 哈希一年仅 ~23KB)。两本账本均已入 08:50 同步白名单 → 永久留存。

**③ 8/03 以来模型路径的变更清单(已审计, `git diff 3ef51c5..HEAD`)**:
- 特征函数 `_compute_rsi` / `_regression_features` / `_compute_rsi_series` / `_compute_vol_clustering` / `_get_macro_features` → **改动行数 0**
- 主模型训练参数(n_estimators/max_depth/learning_rate/reg_lambda/reg_alpha/subsample/colsample/scale_pos_weight/random_state) → **改动行数 0**(diff 中出现的 XGBClassifier 是 9/1 新增的 RESIDUAL **影子**模型, 不碰主模型)
- **唯一模型路径改动 = ETF 2 维置零(8/5, 2/946 维)**; 其余提交均为执行/监控/报表/影子臂
- 训练可复现性: 生产自己的 npz + 生产原参数 → 复现生产模型 **Spearman 0.9354 / top10 8/10**
- **不可证的部分(诚实边界)**: 逐位复现历史预测物理上不可能 — 外部数据文件每日被采集器重写(`last_added_date` 即当日),
  历史时点值不可复原; 且模型文件不留存。**"同一个模型"的准确表述 = 同一条流水线 + 不同时点的数据。**

## 8.4 模型水准测评 · 六层判读(2026-09-13 立, 用户指示"写进agent以便以后复查" + SKILL「模型水准测评」)

- ③ 底率分档(每笔U 均值/**中位**/剔TOP3/到期单均): 荒 **−3.92/−9.43/−10.24/+30.06** ｜ 偏紧 **−1.47/−6.65/−8.49/+34.57** ｜ 正常 **+18.74/+12.31/+6.05/+106.36**

  → **收益提升几乎全部来自持有时长(48h→72h), 放宽止损只是次要放大器**

- **生产影响**: **零** —— 封禁窗口内无生产任务(01:31/01:41 每小时对账在封禁前完成; 02:31/02:41 在解封后完成;
  早间流水线 06:00 起更不受影响)。**但这是运气, 不是设计** —— 若封禁发生在 06:00~09:00, 会连锁打断
  「采集→训练→预测→实盘→影子结算」整条链
- **元教训**: **实验与生产共享 IP = 共享限流预算 = 实验能威胁生产** → 这是"另开一台机器做数据"的正当理由

**④ 若确需走 API(仅限少量/实时查询, 不做批量)**
- 速率 **≤2 req/s**(≈600 权重/分钟, 留 4 倍余量); 避开 **06:00~09:00** 生产高峰
- 遇 418/429 **立即停止**(继续请求会**延长**封禁), 记下 `banned until` 时间戳后等它自然过期
- 生产自用端点(结算拉 1m 等)属必要开销, 但**同样吃这份预算** → 实验必须让路

**⑤ 存储纪律**
- **只存派生量, 原始分钟数据不落盘**(ZIP 边下边聚合)。实测 399币×135天 派生量仅 **21MB**(原始 1m ≈7GB)

## 8.6 特征/因子筛选口径 —— **尾部口径, 不是 IC**(2026-09-14 立, 修正铁律7的执行细节)

> **背景(必须读)**: 2026-09-14 实测发现 **IC 对"SL封顶 + 右尾敞开"的系统是错指标**。
> 案例: `rv`(前一日1m已实现波动) 的 IC = **−0.094**(看起来"低波动优选", 且与已有振幅维相关 0.88 被判"冗余"),
> 但按尾部口径它是 **8.46 倍右尾率差** —— IC 只看均值/中位, **看不见分布形状的变化**;
> 而我们的系统恰恰不吃均值、吃右尾(公理1)。

**① 正确的筛选判据(替代 |IC|≥0.03)**

| # | 判据 | 门槛 |
|---|---|---|
| 1 | **分档右尾率单调性**(≥+33% 命中率, 按特征分5档) | 单调(或严格反向) |
| 2 | **最高/最低档倍数** | >1.5x 且**两 regime 段都成立** |
| 3 | **95% 置信区间**(Wilson) | 最高/最低档 **CI 不重叠**(稀有事件必须给区间!) |
| 4 | **到期单均**(尾部肥度) | 随档位单调改善 |
| 5 | **结构下每笔U**(SL-8%/72h/无止盈, 300U) | 用作经济价值的确认, **非首要判据** |
| 6 | 与已有维度的**增量** | 正交化后**尾率差仍成立**(不是用正交化后的 IC!) |

**② 实测结果(2026-09-14, 399币×135天/48,886样本, 跨2 regime段)**

**★ 分风格稳定性(2026-09-14 实测, 用户判断"rv 约等于无视市场风格变化" → 成立但需精确化)**
> 脚本 `~/micro_data/regime_stability.py`

| 维度 | 分档 | rv高−rv低 右尾率差 | rv高−rv低 每笔U差 |
|---|---|---|---|
| 供给(底率) | 荒 / 偏紧 / 正常 | **+6.25 / +8.33 / +6.06 pp** | +1.03 / +2.21 / +1.51 U |
| BTC 当日 | 跌 / 平 / 涨 | **+8.72 / +4.84 / +6.20 pp** | +2.10 / +1.06 / +1.33 U |
| BTC 5日趋势 | 跌 / 震荡 / 涨 | **+9.62 / +4.64 / +10.32 pp** | +8.69 / **−0.57** / **−0.27** U |

- ✅ **"抓右尾"是风格无关的**: 9/9 分档右尾率差全为正(4.6~10.3pp)。对比: **底率/IC/EMA纠缠闸门全都风格依赖** → **rv 是第一个换风格不失效的杠杆**
- ⚠️ **"净收益优势"部分风格相关**: 每笔U差在 BTC 5日趋势的【震荡/上涨】档微负 → 尾巴更多但**止损拖累也更大**
- **机制(为什么能无视风格)**: ① 物理基础是**波动聚集**(rv 自相关 **0.794**, 与方向无关);
  ② 用法是**同日池内相对排序**(每天重排) → 低波动期挑"相对最抖的" → **自动适应风格**;
  ∴ **"无视风格"的来源不是 rv 有魔法, 而是"相对排序天然风格中性"**。
  **任何绝对阈值(如 "rv>10%")反而会变成风格依赖** —— 低波动期一个币都选不出来
- **2×2(rv × 距20日低点)证明 rv 与 C远 是同一现象的两面**:
  `rv高×C远(>33%)` 297笔 +3.00U/笔 尾率9.76% 止损率64% ｜ `rv高×C近(<15%)` 78笔 +0.66U 2.56% ｜
  `rv低×C近` 289笔 +0.40U 0.35% ｜ **`rv低×C远` = 0 笔**(逻辑必然: 距20日低>33% ⇒ 涨33%+ ⇒ 日内不可能平静)
  → **跨币比较时 rv高 ≈ "这币已经涨过了"(追高指标)**; **只有【同日池内比较】时 rv 才是纯"路径长度"**
  → 顺带: 金矿格 = C远×V高, 而 C远 隐含高波动 → 金矿格的效力可能部分来自波动而非量能(待另验)

**④ 三条硬约束(踩过的坑)**

1. **只能用于精选池内, 不能当全宇宙筛选器**: 池放宽到前30/前50 时, rv高档的每笔U优势消失甚至反转
   (+0.71U vs 低档 +2.19U) → **价值只在"模型已筛掉噪声"之后兑现** → 用法是**池内加权/再排序**, 不是当全宇宙闸门
2. **全宇宙五档的每笔U几乎相同**(rv: +1.15/+0.57/+0.31/+0.30/+0.31), 差别全在**分布形状**(大赢家 52→440)
   → 只看每笔U 会误判"这特征没用"; **必须看尾部率/大赢家数**
3. **不能替代模型选币**: rv 与已有振幅维相关 **0.859**、波动率 0.667 → 大部分信息重复;
   增量只在**尾部概率**上且只在池内 → 别指望"新维度"级别的提升
