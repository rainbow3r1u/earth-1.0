## 2. 两起事故 + 三个护栏（本窗口最危险的发现）

### 2.1 §7.13 撤单函数静默失效（上线起从未生效）

- **端点写错**: `DELETE /fapi/v1/algoOrders`(复数) → **404**;正确是单数 `/fapi/v1/algoOrder`
- **成功判据写错(更隐蔽)**: `signed()` 出错时返回 `{'error':True,'http_code':404}`(**无 `code` 键**),而判据是 `r.get('code') not in (None,200)` → `None` 被判**成功** → 函数直接 return,下面的兜底永不执行
- **修复**: 新增 `_algo_ok()` 显式排除 error 响应;端点改单数
- **教训**: 任何"HTTP 错误被当成成功"的判据都要显式检查 `error`/`http_code`

### 2.2 §7.14 孤儿仓事故（迁移 SL 档位时）

- **根因**: 我用 `close_one(sym,st,'止损')` 去"主动平仓" —— 但 `close_one` **对非「到期」原因不下市价单**(它假定交易所已平掉)
- **后果**: 6 笔(果3+刘3)仓仍在交易所、账本已被删 → 无人管理的孤儿仓
- **护栏**: 两个执行器新增 **`close_market()`** —— **主动平仓必须走它,不要用 close_one**

### 2.3 §7.15 嵌合记录事故（孤儿仓裸奔 7 小时,本窗口最严重）

- **现象**: `st['open']` 出现键=`BRUSDT`、`symbol`字段=`BRUSDT`,但 `qty/entry/sl/tp/open_time/tag` **全是 BSBUSDT 的**记录
- **后果**: 08:41 对账按 `BRUSDT` 处理 → 交易所没有该仓 → 判"已离场" → 删出账本 + 撤条件单 ⇒ **交易所 1366 张孤儿 + 无SL无TP裸奔约 7 小时**
- **根因(证据链完整)**: `data/hybrid_live_state.json` 是 **git 跟踪 + 日更 + 日同步** 的文件;08:30 公证的 `git add -A` 把它提交进快照,随后 `git rebase` 要**三方合并**本地版与远程版 → **JSON 逐行合并 ⇒ 键行/值行可能来自不同版本**
  - 这是 **§7.10 记录过的冲突类别 —— 当时只修了 `residual_live_state.json`,漏了 `hybrid_live_state.json`**
  - 已排除: 代码无 `sym` 重赋值 / 无重复函数定义 / `save_state` 是原子写 / 无三方进程 / 当日候选无 BRUSDT
- **修复**: 还原 BSBUSDT 到账本(用交易所 entry/qty + 日志里执行器**原算的** SL/TP)+ 重挂 + 删脏记录 + 三向核对 15==15

### 2.4 ★ 新增护栏 `integrity_check(st)`（两个执行器都有）

在 `reconcile()` **最前面**调用(**必须在 `if not st['open']: return` 之前** —— 否则"账本空但交易所有仓"这个最危险的情形会被跳过),检两类:

## 9. 踩坑清单（本窗口实测）

1. **手工测试掩盖 bug**: `br_forecast.py` 手工测时目标日恰在缓存里 → 每日 08:00 必崩却测不出来(§4.1)
2. **搜索盲区**: 找「止损建议」时只 grep `daily_digest_email.py`,零命中 —— 该文案在**外部模块** `audit/forward_settle.py` 里。**排查渲染问题要连被调用的模块一起搜**
3. **同名不同义的"窗口"**: "TP 限48h"(撤止盈单,放开第3天) ≠ "持 48h"(48h平仓,第3天不存在)。**凡两个概念共用一个数字,必须当场画并排对照表**
4. **字体字形要先验证**: 规则行首 `▬`(U+25AC)不在 Noto CJK 里 → 用 `fontTools` 查 cmap 表确认后再用
5. **f-string 嵌套引号**: 多次 SyntaxError。**把格式化挪出 f-string,先算好字符串再插值**
6. **补丁脚本的锚点要幂等**: 断言失败会让整个脚本中止(前面已做的替换不会写盘),重跑要能识别"已改过"
7. **`.trae` 被 gitignore**: 本地 `git add` 会被拒(报 "paths are ignored"),但它走 08:50 Contents API 同步;`.agents` 反过来
8. **user 粘贴重复**: 用户两次粘贴内容时重复了同一段(酒店点评、交易摘要),**先核实信源再当成 bug 处理**(实测晨报里只出现 1 次)
